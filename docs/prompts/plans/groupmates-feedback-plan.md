## Recommendation: Phase 30C first, then the feedback as Phase 30D

1. **F9, the most useful point, needs 30C.** "Returned to supplier" only exists once 30C gives the
   FM the Return to supplier decision. Doing the Materials work first means building the split
   twice or leaving it half done.
2. **30C is CPoint's own requirement** (C-9, C-35 to C-37) and the paper's main camera claim; the
   feedback is the team's polish on one report and one form. 30C is also the riskier one (slanted
   cuts, the area share by box), so it should get the time while there's slack.
3. **Nothing in the feedback is a data fault.** F1 clutters the history but changes no batch or
   report (newest save wins). Nothing is wrong in a demo meanwhile.
4. **Phase 31 (docs and figures) goes last either way,** so both 30C and 30D are in the paper.

The only argument for feedback first is that it is quicker and the team sees their notes acted
on. If that matters, F1 alone is a small standalone fix that can go first without touching 30C.

## Phase 30D: the feedback (after 30C)

  under the Save button; the history keeps one row per change. Unit tests.

  URL as `?week=YYYY-MM-DD`); no Last 8 weeks, no Per 100 pairs; On hand at week end for both
  weeks with the change; Leather rolls per week: Fully used, Returned to supplier, Removed (other),
  rolls checked, pairs finished, the change in pairs, pairs per roll used; CSVs to match.
- **F7 check:** find why pairs finished was 0 (their database first, then the query).
- **Docs:** D-entry amending D-102 (no per 100 pairs, week picker, the split); STATUS; handoff and
  Codex prompt.
- Out of scope: per-day leather deduction from scans (F8, D-104 stands).
