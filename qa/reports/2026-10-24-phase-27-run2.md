## 4. Failures

### F1 — R2: supplier deactivation e2e test times out

- **Severity:** Medium
- **Role / page:** System Admin settings and Floor Manager Reports → Rolls test flow
- **Steps to reproduce:** Run the full suite or npm run test:e2e -- tests/e2e/admin.spec.ts --workers=1. The test creates a supplier in Settings → Suppliers, navigates to /admin/settings (the default Thresholds tab), then tries to locate that supplier row and click Deactivate.
- **Expected:** The supplier row is available to deactivate.
- **Actual:** Test timeout of 30000ms exceeded. Error: locator.click: Target page, context or browser has been closed. The call log waits for getByRole('row', { name: '<dynamic E2E Supplier>' }).getByRole('button', { name: 'Deactivate' }) and times out at tests/e2e/admin.spec.ts:240.
- **Rerun:** Same failure in the isolated admin.spec.ts rerun; 5 other tests passed.
- **Evidence:** artifacts/2026-10-24-phase-27-run2/rerun-admin.log.
- **Assessment:** The test appears to be on the wrong Settings tab. It navigates away from ?tab=suppliers at line 228, then looks for the supplier row at lines 237–240 without returning to the Suppliers tab. This looks like a test issue.

### F2 — R2: auth e2e tests still expect “Production” navigation

- **Severity:** Medium
- **Role / page:** Floor Manager, Quality Inspector and System Admin sidebars
- **Steps to reproduce:** Run the full suite or npm run test:e2e -- tests/e2e/auth.spec.ts --workers=1.
- **Expected:** The test's EXPECTED_NAV arrays currently expect “Production”.
- **Actual:** The application sidebar reports “Batches”, as Phase 27 requires. At tests/e2e/auth.spec.ts:42, the assertion diff is Expected “Production”, Received “Batches” for the manager, inspector and admin cases.
- **Rerun:** All three failures persisted alone; the other 9 auth tests passed.
- **Evidence:** artifacts/2026-10-24-phase-27-run2/e2e.log and e2e-rerun.log.
- **Assessment:** The test expectation is stale. Suspect tests/e2e/auth.spec.ts:18-23; this is not an application navigation failure.

### F3 — R2: lunch-break e2e test times out on a disabled field

- **Severity:** Medium
- **Role / page:** System Admin, Admin → Settings → Lunch break
- **Steps to reproduce:** Run the full suite or npm run test:e2e -- tests/e2e/batches.spec.ts --workers=1.
- **Expected:** The Admin can fill Lunch starts and reach the validation messages.
- **Actual:** Test timeout of 60000ms exceeded. Error: locator.fill: Test ended. At tests/e2e/batches.spec.ts:172, Playwright resolved lunch-start to a disabled time input and repeatedly reported “element is not enabled”. The captured Playwright page context showed a Floor Manager on Plan batches and quota, rather than the expected Admin settings page; see e2e-batches-lunch-error-context.md.
- **Rerun:** Same failure in the isolated batches.spec.ts rerun; 1 test passed and 4 later serial tests did not run.
- **Manual check:** A direct Admin sign-in on the same built app reached /admin/settings?tab=lunch; both time fields were enabled and showed 11:00 and 12:00. Screenshot: artifacts/2026-10-24-phase-27-run2/screenshots/e2e-failure-admin-lunch-manual.png.
- **Assessment:** The app form worked in the manual Admin check. The e2e session/page state is inconsistent with the test's expected role and route; likely a test setup/context issue around tests/e2e/batches.spec.ts:169-172.
