## 4. Failures

### Setup — initial demo reset hit a foreign-key constraint

- **Severity** — Medium. QA could continue using existing demo data.
- **Steps** — With only Docker `db` running, run `npm run db:up`, `npm run db:deploy`, then `npm run demo:reset '--' --yes`.
- **Expected** — Reset completes and seeds a fresh demo week before QA.
- **Actual** — Reset exited 1 at `src/server/models/demo-reset.model.ts:101` on `db.roll.deleteMany()` with `Foreign key constraint violated on the constraint: scans_batchId_fkey`. At startup, the app logged “Demo week not seeded” because rolls already existed.
- **Evidence** — Initial reset terminal output and [dev server startup log](artifacts/2026-11-26-phase-41/dev.log).

## 5. Other observations

- A roll search submitted immediately after a direct desktop navigation initially showed the empty-input message. Re-entering the code returned the expected roll. The complete Inventory → Find roll → search → Inventory flow subsequently passed without retry.
- After stopping the dev server, `npm run demo:reset '--' --yes` completed successfully in 93 seconds (exit 0) and seeded 250 rolls, 1,139 scans and 9 days of attendance. Only Docker `db` remained running. [Final reset log](artifacts/2026-11-26-phase-41/final-demo-reset.log)
- Vault steps were omitted as requested.
