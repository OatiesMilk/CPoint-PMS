## 4. Failures

### F1 — E1 and E2: Settings cannot find the generated defect type row

- **Severity:** Low
- **Role / page:** System Admin, Settings → Defect types.
- **Steps to reproduce:** The test inserts the e2e defect types, opens Defect types, fills Find defect type with e2e-clean-only, then looks up a row by accessible name.
- **Expected:** The matching row is found and contains “Clean before cutting”.
- **Actual:** The row is visible in the table, but its accessible row name is “E2E stain”; e2e-clean-only is in a separate cell. The locator matches the row's accessible name, so it never finds the row. The same assertion fails in both full runs and in the isolated test.
- **Exact error:**

  Error: expect(locator).toContainText(expected) failed
  Locator: getByRole('row', { name: /e2e-clean-only/ })
  Expected substring: "Clean before cutting"
  Timeout: 10000ms
  Error: element(s) not found

- **Failing line:** tests/e2e/cut-around-or-clean.spec.ts:78.
- **Passed when run alone?** No. The isolated test reproduced the failure.
- **App or test:** Test issue. The error context confirms the row and expected handling text are present; the test assumes the class-key cell contributes to the row's accessible name.
- **Evidence:** [Run 1 log](artifacts/2026-10-20-phase-20-qa-run3/e2e-run1.log) · [Run 2 log](artifacts/2026-10-20-phase-20-qa-run3/e2e-run2.log) · [Isolated run log](artifacts/2026-10-20-phase-20-qa-run3/cut-around-settings-alone.log) · [Playwright error context](artifacts/2026-10-20-phase-20-qa-run3/cut-around-settings-error-context.md)
- **Smallest fix:** In tests/e2e/cut-around-or-clean.spec.ts:78 and :82, select the row by visible cell text, for example page.getByRole("table").getByRole("row").filter({ hasText: CLEAN_KEY }) and the equivalent CUT_KEY locator.
