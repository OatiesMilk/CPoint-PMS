## 4. Failures

### F1 — L4, seven rows spill across two A4 pages

- **Severity** High.
- **Role / page** Floor Manager, roll-label print view.
- **Steps** Open `/inventory/labels?rolls=<21 in-stock roll IDs>`. The run used 21 distinct demo rolls. Save with Chromium `page.pdf()`, A4, CSS page size preferred and scale 100%.
- **Expected** The preview reads “An A4 sheet of 3 × 7 stickers. Print at actual size (100%), then stick each label on its roll.” The first page should contain 21 labels in seven rows of three.
- **Actual** PDF page 1 contained 18 labels in six rows. Page 2 contained `LR-BSB-050`, `LR-BSB-051` and `LR-MSA-085`. Both pages were 594.96 × 841.92 pt (A4).
- **Suggested fix** Check the print page box and row heights in `src/app/globals.css`. Seven 42.3 mm rows need 296.1 mm. The 12.9 mm top margin leaves 284.1 mm on a 297 mm page.
- **Evidence** [Pages side by side](artifacts/2026-11-18-phase-32-roll-locations-run1/l4-pdf-pagination.png) · [Page 1](artifacts/2026-11-18-phase-32-roll-locations-run1/full-sheet-21-labels-1.png) · [Page 2](artifacts/2026-11-18-phase-32-roll-locations-run1/full-sheet-21-labels-2.png)

### F2 — L10, bulk move origins are missing from the Before column

- **Severity** Medium.
- **Role / page** System Admin, Audit log.
- **Steps** As FM, move three stored rolls from two bins to `R2-B2` and enter “Rack full”. As Admin, filter by `roll.move` and expand the entry with that note.
- **Expected** The entry shows previous locations under Before and the new location under After.
- **Actual** All Before cells showed “—”. After contained `to = R2-B2` and an array of rolls with embedded origins `R9-B1`, `R9-B1` and `R1-B2`. The underlying audit row had no Before payload. Individual roll histories showed their moves correctly.
- **Suggested fix** Record the previous roll/location pairs in the bulk move's audit Before payload in `src/server/services/roll.service.ts` so the existing diff renderer can show the change.
- **Evidence** [Audit payload](artifacts/2026-11-18-phase-32-roll-locations-run1/l10-audit.log)

### F3 — L12, full-suite timeouts and a claim-sheet locator collision

- **Severity** High for the regression check. The claim sheet itself opened and showed the expected defect share before the locator assertion failed.
- **Role / page** Multiple roles on the dev server. The isolated selector failure was on the Floor Manager's claim sheet.
- **Steps** Run the five handoff specs and then `npm run test:e2e` against the dev server. Rerun each spec that reported a timeout or aborted navigation separately, with two workers and the same timeouts.
- **Expected** The existing tests pass under the applicable demo and model settings.
- **Actual** The six-worker runs had test deadlines and navigation waits. For example, the full-suite inventory test at `inventory.spec.ts:267` stopped with `Error: page.goto: Test timeout of 30000ms exceeded.` The full-suite Capture access test expected `http://localhost:3001/batches` after sign-in and received `http://localhost:3001/` at the 10 s assertion timeout. The phone Capture test at `capture.spec.ts:332`, which exercises the Put roll back dialog, passed. The new navigation checks passed, and the inventory add-roll workflow passed on its isolated rerun.
- **Isolated claim-sheet failure** `tests/e2e/returns.spec.ts:182` reported the following. The expression matched the “Returned to supplier: defects …” banner and the detail value “Over the 10% limit”.

  ```text
  Error: strict mode violation: getByText('Over the 10% limit') resolved to 2 elements:
      1) <span class="font-medium">…</span> aka getByText('Returned to supplier: defects')
      2) <dd class="text-sm text-muted-foreground">Over the 10% limit</dd> aka getByText('Over the 10% limit', { exact: true })
  ```

- **Suggested fix** Scope the claim-sheet assertion to the intended detail value. Investigate the six-worker dev-server navigation delays separately.
- **Evidence** [Targeted run](artifacts/2026-11-18-phase-32-roll-locations-run1/e2e-targeted.log) · [Full run](artifacts/2026-11-18-phase-32-roll-locations-run1/e2e-full.log) · [Isolated returns](artifacts/2026-11-18-phase-32-roll-locations-run1/e2e-isolated-returns.log) · [Isolated summary](artifacts/2026-11-18-phase-32-roll-locations-run1/e2e-isolated-summary.log)

## 5. Other observations

- The visible “Set aside” action on the skipped roll had accessible name “Move LR-BSB-049”. A screen reader user may hear a different action than the one displayed.
- The saved-location toast overlaid the last row's Deactivate button in the in-app viewport. Its hover state kept it visible, and clicking the covered area did not reach Deactivate. Keyboard activation let the L1 workflow proceed.
- The fake Capture stream was live after the QR modal closed. Whether a real phone pauses Capture while the second stream is open still needs the device check named in the handoff.

## 6. Suggested fixes in priority order

1. Fit the seventh row on the A4 page at actual size and verify a full 21-label sheet.
2. Show the bulk move's origin locations in the audit Before payload.
3. Scope the claim-sheet assertion to the intended defect-limit value and investigate the navigation delays under six-worker dev-server load.
