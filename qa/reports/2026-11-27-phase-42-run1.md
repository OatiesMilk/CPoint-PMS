## 4. Findings

### F1 — T8 digits validation differs between the browser and API

- **Severity** Medium. Floor Manager, Inventory → LR-001 → Add rolls.
- **Steps** Fill three valid Areas. Type `12a`, `0`, and `1234567` in the three Digits boxes. Save.
- **Expected** The handoff calls for an error on each row.
- **Observed** The letter was stripped and the seventh digit was blocked. The preview showed “Code: LR-BSA-012”, “Code: LR-BSA-137”, and “Code: LR-BSA-123456”. Only row 2 showed “Roll 2: type the digits after the tag, like 001 (up to 6 digits). Leave them empty for the next free number.” The request using the three raw strings returned 422 with that error for each respective row.
- **Cause** The Digits input removes non-digits in its change handler and sets `maxLength={6}`. Align the handoff with that input behavior, or keep the invalid characters visible if the row error is the intended browser behavior. [Screenshot](artifacts/2026-11-27-phase-42/T8-digit-errors.png), [browser and API results](artifacts/2026-11-27-phase-42/manual-results.json)

### F2 — T9 an overlength tag code is silently truncated and saved

- **Severity** Medium. Floor Manager, Inventory → Roll tags.
- **Steps** Open Add tag, type `ABCDEFG` and save.
- **Expected** “Enter a tag code of 2 to 6 capital letters or digits, starting with a letter, like BLC.”
- **Observed** The browser accepted six characters and Create saved `ABCDEF` for “Any supplier”. The toast read “ABCDEF added.” The same format error appeared for `1x`.
- **Cause** The Code input's `maxLength={6}` truncates the typed value before the validator can inspect it. Preserve the attempted value for validation if the handoff's error is intended. [Screenshot](artifacts/2026-11-27-phase-42/T9-ABCDEFG.png)

### F3 — Inventory e2e timed out waiting for roll removal

- **Steps** Run the test at [inventory.spec.ts:267](../../tests/e2e/inventory.spec.ts#L267). Add two rolls, remove the 31.75 sq ft roll with a reason, and wait for the on-hand display.
- **Expected** The Remove dialog closes and stock shows “1 roll”.
- **Observed** The first run timed out with “2 rolls” still visible. The rerun timed out as the dialog reached `data-state="closed"`. PostgreSQL subsequently showed the 31.75 sq ft roll as `CANCELLED` and stock at 1 for both fixtures.
- **Assessment** The DB supports a timing failure in the e2e run. The removal persisted correctly. [First log](artifacts/2026-11-27-phase-42/e2e-inventory.log), [rerun log](artifacts/2026-11-27-phase-42/e2e-inventory-rerun.log), [SQL](artifacts/2026-11-27-phase-42/e2e-inventory-db-evidence.txt)
