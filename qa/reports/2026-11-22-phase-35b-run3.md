## 4. Failures

### F1 — C12: inspection-queue fixture assumes Saturday is older than Sunday

- **Severity:** High for the required e2e gate; test-fixture/expectation defect, with no queue-sort defect demonstrated.
- **Role / page:** Quality Inspector → Batches Queue; `tests/e2e/inspection-queue.spec.ts:114`, first case.
- **Steps to reproduce:** Run the unchanged inspection-queue spec on Sunday, 22 November 2026, in Asia/Shanghai/Manila time, against this dev server and seeded database. Its `lastWeekend()` selects the most recent Saturday and Sunday strictly before today.
- **Expected:** Normal-priority batches should be ordered chronologically, oldest first. On this date, Sunday 15 Nov must precede Saturday 21 Nov. The test must choose an appropriately ordered fixture pair or compare their actual dates.
- **Actual:** The selected fixtures are Saturday `2026-11-21` (`B-261121-1`) and Sunday `2026-11-15` (`B-261115-1`). In the related run, the app puts the older Sunday first (index 1) and Saturday later (index 2), after an existing urgent batch. The assertion unconditionally requires `codes.indexOf(SAT) < codes.indexOf(SUN)` and fails with **Expected < 1, Received 2**. The full run repeats the same relative ordering failure at indices 2 and 3 (**Expected < 2, Received 3**), with other concurrent fixtures present. Its three subsequent serial cases do not run in either invocation. This failure precedes the toast wait changed for run 3 and is not a timeout, focus failure or SQL timestamp mismatch.
- **Evidence:** `fixture-dates.json`; `related.log`, `related-results.json`; `e2e-related/inspection-queue-the-queue-abe70-e-oldest-first-with-filters-chromium/error-context.md`; unchanged source's `lastWeekend()` and the oldest-first assertion at line 133. Isolated and full-run counts are in the automated table.
- **Suggested fix:** Claude should select one completed Saturday/Sunday weekend consistently (rather than independently selecting each weekday before today), or derive the expected order from the fixture dates while keeping the oldest-first assertion. Do not change the app's correct chronological ordering, skip Sunday, move the demo clock, or loosen the test to obtain a pass.
