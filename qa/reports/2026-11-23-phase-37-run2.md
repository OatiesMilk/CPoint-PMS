## 5. Other observations

- The first `npm run demo:reset '--' --yes`, after the clock was changed and the dev server restarted, produced only 10:30 rows. The CLI reset runs in its own process and does not inherit the dev server’s cached demo-clock offset. A headless reset through the login page in that server process seeded the expected times. Evidence: `W4-cli-reset-clock-result.txt`, `reset-at-1600.log`, `clock-aware-reset.log`.
- The first count-entry script parsed the displayed `15pairs` without its missing space and entered invalid `NaN` in the form; no save request reached the server and no row was created. A corrected headless run saved 16 and verified the changed card time and SQL row. Evidence: `W4-save-diagnostic.log`, `W4-headless-save2.log`, `W4-SQL-after-count.txt`.
- The clock offset was set back to 0; the final demo reset completed. The dev server was stopped, port 3000 is closed, and only the Docker `db` service remains running. Evidence: `clock-restored.txt`, `final-reset.log`.

## 6. Suggested fixes (priority order)

1. For clock-sensitive W4 setup, use the app’s login-page Reset demo control after restarting the server; the standalone CLI reset currently seeds with its own real-time process clock.
