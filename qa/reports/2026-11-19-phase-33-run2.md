## 4. Failures and blocked checks

### F1 — Q3: Clear retains the previous Batch code in the field

- **Severity** Medium.
- **Steps** In the QI Queue with Saturday and Sunday batches, search for code `261115-1`. Click Clear, select Sat, 14 Nov, and click Filter.
- **Expected** The code field clears, and the day filter shows `B-261114-1`.
- **Actual** The field still showed `261115-1` with Sat, 14 Nov selected. The page displayed “No waiting batch matches these filters.” Playwright returned `Error: element(s) not found` for `getByTestId('queue-B-261114-1')` at `inspection-queue.spec.ts:143`.
- **Evidence** [Playwright page snapshot](artifacts/2026-11-19-phase-33-run2/e2e-targeted-results/inspection-queue-the-queue-abe70-e-oldest-first-with-filters-chromium/error-context.md).
- **Suggested fix** Reset the filter form’s current values when Clear navigates to the unfiltered queue.

### F2 — Q9: Earlier-day inspected batch has no Correct action

- **Severity** High.
- **Steps** On Friday, finish Thursday’s B-261119-2 and look for Correct in Inspected and void. Call the normal correction API on Friday, then move the demo clock to Saturday at 09:00 and repeat.
- **Expected** The inspector can correct the batch from the UI on Friday. On Saturday the service refuses with the inspection date.
- **Actual** The historical row showed the counts and inspection timestamp with zero action buttons. The Friday API request returned HTTP 200 and displayed 22 pairs, 1 failed on reload. Saturday returned HTTP 409 with `A batch can only be corrected on the day it was inspected. This one was inspected on Fri, 20 Nov.`
- **Evidence** [Browser log](artifacts/2026-11-19-phase-33-run2/manual.log), [Friday API](artifacts/2026-11-19-phase-33-run2/q9-api-inspection-day.log), [Saturday API](artifacts/2026-11-19-phase-33-run2/q9-api-next-day.log).
- **Suggested fix** Provide a Correct action for eligible historical rows under Inspected and void, using the inspection-day eligibility rule.

### F3 — Q13: Inspect button measures 36 CSS px on mobile

- **Severity** Medium.
- **Steps** Set the in-app viewport to 390 × 844, open the QI queue and measure the two action buttons on the waiting card. Click Inspect.
- **Expected** Both actions measure at least 44 px, with a bottom sheet and no sideways overflow.
- **Actual** Start inspection was 44 px and Inspect was 36 px. The Finish dialog spanned the 390 px viewport and reached its 844 px bottom edge, with no sideways overflow.
- **Evidence** [Browser geometry and dialog](artifacts/2026-11-19-phase-33-run2/manual.log).
- **Suggested fix** Use a 44 px minimum height for the Inspect action on the queue’s phone layout.

### F4 — Q14: Playwright suite assertions failed

- **Severity** High.
- **Steps** Against the verified dev server, run the two targeted Playwright specs and then the full suite with two workers.
- **Expected** Both suites pass.
- **Actual** Both runs reported `Error: element(s) not found` after 10,000 ms for `getByTestId('no-batches')` at `batches.spec.ts:274`, expected text `No batches yet today. The Floor Manager plans them first.`, and for `getByTestId('queue-B-261114-1')` at `inspection-queue.spec.ts:143`, expected visible. Serial dependencies account for the 8 tests that did not run in each suite.
- **Evidence** [Targeted log](artifacts/2026-11-19-phase-33-run2/e2e-targeted.log), [full log](artifacts/2026-11-19-phase-33-run2/e2e-full.log), [no-plan page snapshot](artifacts/2026-11-19-phase-33-run2/e2e-targeted-results/batches-a-weekday-with-no--2be34-er-is-told-to-plan-it-A-37--chromium/error-context.md).
- **Suggested fix** Address F1. In the no-plan test, account for the inspector now landing on Queue and open Today before checking its no-plan message.
