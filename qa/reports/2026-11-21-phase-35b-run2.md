## 4. Failures

### F1 — C11: Remove roll still loses focus after dismissal

- **Severity:** Medium
- **Role / page:** Floor Manager, Reports → Rolls → an In stock roll (`LR-BSA-126` in this run).
- **Steps to reproduce:** 1. Open the roll and activate **Remove roll…**. 2. Close with Escape; repeat with **Keep roll** and the top-right X. 3. Repeat in dark mode.
- **Expected:** Each dismissal closes the dialog and returns `document.activeElement` to the exact Remove roll… button that opened it.
- **Actual:** The dialog closes, but BODY becomes active in all six in-app checks. Headless Playwright `toBeFocused()` also failed after waiting its normal five seconds, in both themes. The two correction dialogs and Add rolls/Plan day all restore focus correctly, so the shared change is only partly effective across the required sample.
- **Evidence:** `c11-in-app-focus.json` has six `focused: false` entries for `remove-roll`. `scenario-evidence.json` records both supplemental `activeTag: "BODY"` results. Screenshots: `c11-remove-roll-light.jpg`, `c11-remove-roll-dark.jpg`, `c11-remove-dark-after-escape.png`.
- **Suggested fix:** Claude should inspect focus capture order between `src/components/ui/dialog.tsx` and the `autoFocus` Reason textarea in `src/components/features/rolls/remove-roll.tsx`. The shared handler captures `document.activeElement` during open autofocus; a child already holding focus is a plausible cause. This is an inference from the source and the contrasting results, not an applied fix.
