## 4. Failures

### F1 — Q14: The immediate Clear and Day sequence still uses the old code

- **Severity** Medium.
- **Role and page** Quality Inspector, Batches → Queue.
- **Steps** In `inspection-queue.spec.ts`, enter Sunday's partial code `261115-1`, filter, click Clear, immediately select Sat, 14 Nov, then click Filter.
- **Expected** The query uses just the selected day and shows Saturday batch B-261114-1.
- **Actual** At `inspection-queue.spec.ts:143` Playwright reported `Error: expect(locator).toBeVisible() failed`, then `Error: element(s) not found` for `getByTestId('queue-B-261114-1')` after 10,000 ms. The snapshot showed `261115-1` still in Batch code, Sat, 14 Nov selected, and “No waiting batch matches these filters.” The separate manual Q3 sequence passed after the Clear navigation finished.
- **Evidence** Both suites reproduced the failure. [Targeted snapshot](artifacts/2026-11-19-phase-33-run3/e2e-targeted-results/inspection-queue-the-queue-abe70-e-oldest-first-with-filters-chromium/error-context.md), [full-suite snapshot](artifacts/2026-11-19-phase-33-run3/e2e-full-results/inspection-queue-the-queue-abe70-e-oldest-first-with-filters-chromium/error-context.md).
- **Suggested fix** Check the filter form during Clear navigation. The old code must be cleared or prevented from being submitted when the user immediately interacts with the form.

### F2 — Q14: The Batches title lacks the due count

- **Severity** Medium.
- **Role and page** Quality Inspector, Batches → Today in the phone test.
- **Steps** Run `batches.spec.ts`'s phone check. Sign in as the inspector, open Today, and read the title after the due banner appears.
- **Expected** The title matches `/^\(\d+\) /` while the due banner is visible.
- **Actual** The coded due banner assertion passed. At `batches.spec.ts:378`, Playwright reported `Error: expect(received).toMatch(expected)`, received `Batches · CPoint PMS`, and `Timeout 10000ms exceeded while waiting on the predicate`.
- **Evidence** Both suites reproduced the failure. [Targeted snapshot and error](artifacts/2026-11-19-phase-33-run3/e2e-targeted-results/batches-the-Quality-Inspec-4db9a-the-batch-with-failed-pairs-chromium/error-context.md), [full-suite snapshot](artifacts/2026-11-19-phase-33-run3/e2e-full-results/batches-the-Quality-Inspec-4db9a-the-batch-with-failed-pairs-chromium/error-context.md).
- **Suggested fix** Check when the title is updated on the Queue → Today navigation and whether the count survives that transition.

- **Severity** Medium.
- **Role and page** Floor Manager, Inventory leather roll area check.
- **Steps** Run the full suite. The Inventory test reads item stock through `GET /api/v1/inventory/{id}`.
- **Expected** The request returns the item for the stock assertion.
- **Actual** The request in `inventory.spec.ts:41`, called by the test at line 267, failed with `Error: apiRequestContext.get: read ECONNRESET`. The isolated rerun passed all eight tests, including this case.
