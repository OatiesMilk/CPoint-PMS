## 4. Failures

### F1 — S7: Escape opens the Return dialog

- **Severity:** Medium
- **Role / page:** Floor Manager, `/reports/rolls/7660a997-8155-4fa1-958d-35346d351ac9`.
- **Steps:** Open Keep, submit with the reason blank, press Escape.
- **Expected:** Keep closes, roll remains in To return, and no decision is saved.
- **Actual:** `Return LR-ES-022 to the supplier?` opens and shows the Keep validation message; it then closes on its own. Database still showed `markedForReturn=true`, `returnDecision=null`.
- **Evidence:** [S7 Escape screenshot](artifacts/2026-11-03-phase-30c/S7-headless-escape.png).
- **Suggested fix:** Review dialog state and Escape/close handling in `src/components/features/rolls/return-decision.tsx` so closing Keep cannot open Return or carry its validation into that dialog.

### F2 — Focused E2E: two assertion failures

- **Severity:** Medium
- **Role / page:** Playwright; `admin.spec.ts` and `rolls.spec.ts`.
- **Steps:** Run the focused suite against the fresh server.
- **Expected:** All focused tests pass.
- **Actual:** `admin.spec.ts:157` expected “Saved. New scans use it from now on.” after saving 45%, but the text was absent; page showed 45% and “No changes yet.” `rolls.spec.ts:74` failed strict mode because “24.5 sq ft” matched two elements. Both failed again in the full suite. The admin test cleanup restored found-at to 50%.
- **Evidence:** [Focused E2E log](artifacts/2026-11-03-phase-30c/phase-30c-focused-e2e-after-restart.log).
- **Suggested fix:** Align the admin success assertion with the observed save response and scope the roll area locator to one field.

### F3 — Full E2E: three additional failures

- **Severity:** Medium
- **Role / page:** Playwright; inventory role-access and two smoke journeys.
- **Steps:** Run `npm run test:e2e` against the fresh server.
- **Expected:** All full-suite tests pass.
- **Actual:** `inventory.spec.ts:319` timed out signing in as Quality Inspector (expected `/batches`, observed `/login` then `/`). `smoke.spec.ts:87` timed out waiting for the newly added inventory item heading. `smoke.spec.ts:149` exceeded the 30-second test timeout during axe analysis. None reported ECONNRESET or a first-compile timeout, so the conditional rerun did not apply.
- **Evidence:** [Full E2E log](artifacts/2026-11-03-phase-30c/full-e2e-after-restart.log) and the `full-test-results` error contexts.
- **Suggested fix:** Investigate the role sign-in and inventory navigation timeouts, and whether the smoke axe timeout is load-sensitive.
