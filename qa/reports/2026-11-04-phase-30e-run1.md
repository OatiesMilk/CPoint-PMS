## 4. Failures

### F1 — Setup: demo reset failed while seeding the demo week

- **Severity:** High
- **Role / page:** Command-line reset and demo inventory seeding
- **Steps to reproduce:** 1. Run db:up, db:deploy, and db:generate. 2. Back up cpoint_pms. 3. Run npm run demo:reset '--' --yes with the backed-up database state.
- **Expected:** Reset completes and creates the fresh demo week.
- **Actual:** Reset printed that it was removing 23 rolls, 114 scans, 8 inventory items, 49 stock movements, 2 stock updates, and 314 audit rows, then exited with “This supplier is no longer active. Choose another supplier.” The restored pre-reset database shows the three demo leather suppliers with isActive=false. Demo seeding resolves these suppliers in src/server/services/demo-seed.service.ts:166 and creates the inventory item at line 246; src/server/services/inventory.service.ts:156 rejects an inactive supplier.
- **Evidence:** Reset output artifacts/2026-11-04-phase-30e/demo-reset.log; retained supplier state artifacts/2026-11-04-phase-30e/restored-db-state.txt; reset and seed implementation at src/server/services/demo-reset.service.ts:207-209, src/server/services/demo-seed.service.ts:166,246, and src/server/services/inventory.service.ts:156. The failure was in the CLI before browser testing, so no browser screenshot was produced.
- **Suggested fix:** Ensure the demo suppliers required by DEMO_INVENTORY are active before seeding, or make reset report a clear precondition before deleting demo data.
